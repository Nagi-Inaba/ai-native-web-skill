# Keep UI libraries operable by AI agents and keyboards

shadcn/ui, Radix UI, and MUI are safer starting points than implementing complex components from scratch. However, using a library alone does not define names, labels, navigation targets, or application-specific state. Inspect the generated DOM and accessibility tree, then complete the library components with the correct information.

## What the library handles

| Component | What the library primarily handles | What remains for the implementation |
| --- | --- | --- |
| Radix `Dialog` / shadcn `Dialog` | Dialog role, modality, focus containment and return, Escape, open and closed attributes | Title, description, action names, domain content |
| Radix `DropdownMenu` | Menu / menuitem roles, arrow-key operation, focus, open and closed attributes | Trigger name, item names, and whether each item performs an action or navigation |
| Radix `Tabs` | Tablist / tab / tabpanel relationships, roving focus, selection attributes | Each tab's name, panel content, initial selection |
| Radix `Accordion` | Trigger inside a heading, expanded attributes, keyboard operation | Heading level, trigger name, content |
| MUI `Dialog`, `Menu`, `Tabs`, `Accordion` | Each component's role, standard key operation, required focus management | Accessible names, labels, descriptions, links, application-specific state |

Do not imitate only the appearance of an existing primitive.

**Incorrect**

```tsx
export function FakeDialog({ open }: { open: boolean }) {
  return open ? <div className="modal">Profile settings</div> : null;
}
```

**Fixed**

```tsx
import * as Dialog from "@radix-ui/react-dialog";

export function ProfileDialog() {
  return (
    <Dialog.Root>
      <Dialog.Trigger>Edit profile</Dialog.Trigger>
      <Dialog.Portal>
        <Dialog.Overlay />
        <Dialog.Content>
          <Dialog.Title>Edit profile</Dialog.Title>
          <Dialog.Description>Change the name shown to your team.</Dialog.Description>
          <Dialog.Close>Cancel</Dialog.Close>
        </Dialog.Content>
      </Dialog.Portal>
    </Dialog.Root>
  );
}
```

Also avoid duplicate implementations, such as overriding the `Dialog` focus trap with another `keydown` handler. Preserve the responsibilities delegated to the library, and provide meaning and state from the application.

## Read state exposed in the DOM

Radix primitives generate `data-state` for styling and `aria-*` for accessibility APIs. Common examples follow.

| Component | State to inspect in the DOM |
| --- | --- |
| `Dialog.Trigger` / `Accordion.Trigger` / `DropdownMenu.Trigger` | `data-state="open"` or `"closed"`, and `aria-expanded="true"` or `"false"` |
| `Tabs.Trigger` | `data-state="active"` or `"inactive"`, and `aria-selected="true"` or `"false"` |
| `Checkbox`, `RadioGroup.Item`, checkable menu items | `data-state="checked"` or `"unchecked"`, and `aria-checked="true"` or `"false"` |

AI agents that inspect DOM attributes and CSS can read `data-state`. `aria-expanded`, `aria-selected`, and `aria-checked` expose state in the accessibility tree for assistive technology and agents using `ariaSnapshot()`. With only one of these, state is missing from some observation paths. Do not remove attributes generated by Radix. In custom components, derive both sets of attributes from one state value.

## Information the implementation must provide

### Name icon-only buttons

Do not rely on an icon name or `title`. Give the button an `aria-label` that includes the action target, and hide the icon itself as decorative. This applies equally to a shadcn/ui `Button` and an MUI `IconButton`.

**Incorrect**

```tsx
import { Trash2 } from "lucide-react";
import { Button } from "@/components/ui/button";

export function DeleteButton() {
  return <Button size="icon" variant="ghost"><Trash2 /></Button>;
}
```

**Fixed**

```tsx
import DeleteIcon from "@mui/icons-material/Delete";
import IconButton from "@mui/material/IconButton";

export function DeleteButton() {
  return (
    <IconButton aria-label="Delete invoice">
      <DeleteIcon aria-hidden="true" />
    </IconButton>
  );
}
```

### Give every dialog a title and description

Use `DialogTitle` and `DialogDescription` with shadcn/ui / Radix. With MUI, use corresponding elements and `aria-labelledby` / `aria-describedby`. Even if the design does not display a title, do not remove it. Hide it visually with `VisuallyHidden` or `sr-only`.

**Incorrect**

```tsx
import { DialogContent } from "@/components/ui/dialog";

export function InviteDialog() {
  return <DialogContent><InviteForm /></DialogContent>;
}
```

**Fixed**

```tsx
import {
  DialogContent,
  DialogDescription,
  DialogHeader,
  DialogTitle,
} from "@/components/ui/dialog";

export function InviteDialog() {
  return (
    <DialogContent>
      <DialogHeader>
        <DialogTitle>Invite a teammate</DialogTitle>
        <DialogDescription>An invitation will be sent by email.</DialogDescription>
      </DialogHeader>
      <InviteForm />
    </DialogContent>
  );
}
```

Express the relationships explicitly with MUI.

```tsx
import Dialog from "@mui/material/Dialog";
import DialogContent from "@mui/material/DialogContent";
import DialogContentText from "@mui/material/DialogContentText";
import DialogTitle from "@mui/material/DialogTitle";

export function ArchiveDialog({ open }: { open: boolean }) {
  return (
    <Dialog
      open={open}
      aria-labelledby="archive-title"
      aria-describedby="archive-description"
    >
      <DialogTitle id="archive-title">Archive project</DialogTitle>
      <DialogContent>
        <DialogContentText id="archive-description">
          Team members will no longer be able to edit this project.
        </DialogContentText>
      </DialogContent>
    </Dialog>
  );
}
```

### Connect form controls to labels

A placeholder is an input example, not a label. Match the `htmlFor` of a shadcn/ui `Label` or MUI `FormLabel` to the input's `id`. For an MUI `TextField`, pass a `label` and a unique `id`.

**Incorrect**

```tsx
import { Input } from "@/components/ui/input";

export function EmailField() {
  return <Input name="email" placeholder="name@example.com" />;
}
```

**Fixed**

```tsx
import FormControl from "@mui/material/FormControl";
import FormLabel from "@mui/material/FormLabel";
import OutlinedInput from "@mui/material/OutlinedInput";

export function EmailField() {
  return (
    <FormControl>
      <FormLabel htmlFor="email">Email address</FormLabel>
      <OutlinedInput id="email" name="email" type="email" />
    </FormControl>
  );
}
```

With shadcn/ui, create the same contract with `<Label htmlFor="email">` and `<Input id="email">`.

### Preserve links as links with `asChild` and `next/link`

Navigation must produce an `<a href>` in the final DOM. Do not place a link inside a button or a button inside a link. shadcn/ui / Radix `asChild` passes presentation and behavior to its child `Link`, preventing nested interactive elements.

**Incorrect**

```tsx
import Link from "next/link";
import { Button } from "@/components/ui/button";

export function SettingsLink() {
  return <Button><Link href="/settings">Settings</Link></Button>;
}
```

**Fixed**

```tsx
import Link from "next/link";
import { Button } from "@/components/ui/button";

export function SettingsLink() {
  return (
    <Button asChild>
      <Link href="/settings">Settings</Link>
    </Button>
  );
}
```

With MUI, make the final element a single link, as in `<Button component={Link} href="/settings">Settings</Button>`. Confirm that DevTools shows `<a href="/settings">`.

### Derive state attributes from the same value in custom components

If CSS and ARIA flags are managed separately, presentation can diverge from the accessibility tree. Derive `data-state`, `aria-*`, and visibility from one React state value.

**Incorrect**

```tsx
export function CustomDisclosure() {
  const [open, setOpen] = useState(false);
  return (
    <div className={open ? "is-open" : "is-closed"} onClick={() => setOpen(!open)}>
      Details
    </div>
  );
}
```

**Fixed**

```tsx
import { useState } from "react";

export function CustomDisclosure() {
  const [open, setOpen] = useState(false);
  return (
    <>
      <button
        type="button"
        aria-expanded={open}
        aria-controls="details-panel"
        data-state={open ? "open" : "closed"}
        onClick={() => setOpen((value) => !value)}
      >
        Details
      </button>
      <section id="details-panel" hidden={!open}>Project details</section>
    </>
  );
}
```

### Do not leave closed content present with CSS alone

Using only `opacity: 0` or moving content offscreen can leave links and inputs in the Tab order and accessibility tree. Unmount closed content, or synchronize `hidden` / `inert` with state. Perform the same check when using `forceMount` to override Radix's default unmounting.

**Incorrect**

```tsx
export function Actions({ open }: { open: boolean }) {
  return (
    <div className={open ? "opacity-100" : "opacity-0"}>
      <button type="button">Delete</button>
    </div>
  );
}
```

**Fixed**

```tsx
export function Actions({ open }: { open: boolean }) {
  return (
    <div hidden={!open} data-state={open ? "open" : "closed"}>
      <button type="button">Delete</button>
    </div>
  );
}
```

## Describe the design system to static checks

Place `ai-native-web.config.json` in the project root. Static checks use this mapping to analyze design-system components as their final native elements. Set `polymorphicPropName` to the prop that switches the element, and use `ignore` for excluded globs.

```json
{
  "components": { "Button": "button", "IconButton": "button", "Link": "a", "NextLink": "a", "Input": "input", "TextField": "input", "Image": "img", "Dialog": "dialog" },
  "polymorphicPropName": "as",
  "ignore": ["src/legacy/**"]
}
```

After configuration, still inspect the final DOM of polymorphic components and `asChild` in the browser. Configuration does not correct runtime DOM.

## Review procedure

1. Use only the keyboard to open, move, select, and close.
2. In DevTools, confirm that the final elements are `button`, `a href`, `input`, and `dialog`.
3. Before and after expanding or selecting, confirm that `data-state` and `aria-expanded` / `aria-selected` / `aria-checked` change together.
4. Check focus immediately after opening and closing a dialog, and confirm that Tab cannot enter a closed panel.
5. Confirm that `ariaSnapshot()` exposes each component's name, role, and state.
